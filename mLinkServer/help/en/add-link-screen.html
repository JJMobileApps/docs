Add Link Screen Guide

1

Target

Set the original server address that will receive the forwarded request.

  • Connection Type: Choose direct IP/domain access or a connected external app target.
  • Protocol: Select `http`, `https`, or `sftp` based on the server you want to connect to.
  • IP Address / Port: Enter the actual target host and port.
  • Use this device IP: Fill the current device IP automatically when the target server is running on this device.
  • Test Connection: Check whether the target server can be reached before saving the link.
2

Link

Set the public domain, path, or connection name that users will use to reach this rule.

  • Match Type: Choose whether the rule matches a domain/host or a local path.
  • Link: Enter the address fragment to publish, such as `cloud.abc.com` or `abc.com/aaa`.
3

Users

Choose which users can use this link rule.

  • All Users: Allow every approved account that matches the active access mode.
  • Selected Users: Limit this rule to specific accounts only.
4

Configure and Use an SFTP Link

To use an SFTP link, the mLinkServer SFTP server must be running. For an SFTP link, register a connection name instead of a domain or path.

  • Register the link: Select sftp as the protocol and enter only a connection name for the link. Example: linkname
  • Connect with an SFTP client: Connect the SFTP client to mLinkServer address:SFTP port.
  • Enter the username: Prefix the actual SFTP username with connection-name/. Example: linkname/sftpuser
  • When login and approval are enabled: The web server must also be running. In a web browser, open mLinkServer-address/linkname, sign in, and complete device approval if required before connecting with the SFTP client. Example: http://192.168.0.10:8080/linkname
  • Approval scope: Access approval completed on the web applies to SFTP client connections from the same IP address.

Save Checklist

  • Make sure the target server is running and reachable on the selected protocol and port.
  • Choose a link value that does not overlap with an existing rule.
  • Review which users can access the rule before saving.

Routing Tip

Keep the target and the link concept separate. The target is the original destination server. The link is the public domain, path, or connection name that points to that target.
